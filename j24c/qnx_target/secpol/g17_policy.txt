# g17_policy.txt - G17b (owner decision V) + G17c: QNX security policy (secpol type policy) for the simulated edge unit and the host. DRAFT.
# Written for the QNX 8.0.6 security policy language from the SDP's own manual (target/qnx/usr/help/.../com.qnx.doc.security.system:
# secpol_language.html, abilities.html, using_security_policies.html): type, allow_attach, channel connect, self:ability, default_spawn_type.
# It has NOT been compiled here: secpolcompile in the SDP is a Linux x86_64 program and this host is macOS, and no QEMU run was made.
# scripts/g17b_qnx_check.sh lints it on the host; scripts/g17_qnx_check.sh --preflight evaluates the probes P0-P6 and the edge unit's own
# access against a model of the documented semantics (opening a path = channel connect to the channel's type; by default a process may
# connect only to channels of type "default"; attaching a path needs allow_attach + pathspace). Compilation (secpolcompile) and enforcement
# (mkqnximage --secpol=secure) are steps of the QNX run; nothing here claims the policy is enforced before the probes of that run say so.
# Simulation wording: "an independent process simulating an ESP-class edge unit (hardware isolation is a design goal)".
#
# Types (G17F: every grant below is what the named program itself does; the probes get their own type where they need more)
#   supervisor_t   v2v-supervisor (root, never drops): spawns the edge unit into edge_unit_t (spawn, settypeid:edge_unit_t), waits for it and
#                  stops it (wait, signal:15); runtime linker (prot_exec, map_fixed); slogger2 (system grants). Root-only blocks: no "nonroot".
#   edge_unit_t    v2v-edge: starts as root (child of the supervisor), loads its keys and opens its FIFOs, then drops itself to uid 1200
#                  (setuid / setgid 1200); reads the radio from a FIFO and reaches the host ONLY through the pipe-manager FIFOs of the boot
#                  commands; attaches no path (G17F: pathspace, public_channel, priority removed - only probes P0 / P3 used them), no
#                  channel to the host, no spawn / fork / io / mem_phys
#   edge_probe_t   G17F, probes only (g17-probe P0 positive control, P3): an edge-unit stand-in that may attach the radio path /dev/v2v_radio
#                  (pathspace, public_channel, priority as learned for P0). No G17 program runs as edge_probe_t. P1 and P5 stay under the
#                  real edge_unit_t.
#   host_srv_t     the resource manager v2v-ttl-resmgr (root: attaches /dev/v2v_ttl, then --drop-uid 1000) and the V2V program
#                  v2v-vehicle-g17 (uid 1000 from its start). G17F: pathspace, public_channel, priority only in a root block (the resource
#                  manager attaches before it drops; a uid-1000 host_srv_t process can attach nothing); may not touch the radio device
#   radio_feed_t   the simulated radio g17-radio-sim (uid 1300; its FIFO is opened by the shell): runtime linker only, connects to no G17
#                  type (G17F: the unused "radio_feed_t -> edge_unit_t channel connect" removed; nothing serves a radio channel in G17)
#   g17_test_t     test harness only (test_iru_proc, test_edge_proc and what they start); outside the isolation claims
# (G17F: car_client_t and its "-> host_srv_t channel connect" removed: no program in the boot commands runs as it.)
#
# Rules this file must keep (g17b_qnx_check.sh lint, g17_qnx_check.sh --preflight): no G17 type connects to host_srv_t (G17c: the former
# "allow edge_unit_t host_srv_t:channel connect;" let an edge-unit process open /dev/v2v_ttl and send devctl, against probe P1; the
# simulation never used it); host_srv_t never connects to edge_unit_t, edge_probe_t or radio_feed_t; neither edge type attaches /dev/v2v_ttl;
# edge_unit_t, edge_probe_t and host_srv_t have no spawn / fork / io / mem_phys ability; radio_feed_t reaches no G17 type; G17F: edge_unit_t
# has no pathspace / public_channel / priority, host_srv_t has them in root blocks only, supervisor_t has no nonroot block, edge_probe_t is
# used only by the probe lines of the boot commands.
# If a host input DEVICE is ever needed instead of the FIFO, it gets its own channel type, never host_srv_t's, e.g.
#   allow_attach host_srv_t /dev/v2v_host_in host_in_t;   allow edge_unit_t host_in_t:channel connect;
# (not declared here: nothing attaches that path in G17.)
#
# G17d (2026-11-14, after the develop boot evidence/g17/qnx_learn.serial.clean.log):
# - In QNX 8.0.6 the generated policy grants connections as the ability "channel_connect:<types>" inside "allow T self:ability { ... }", with
#   a "nonroot" block (also for non-root processes) and a root-only block. Connections of the G17 types to SYSTEM services (pipe_t, random_t,
#   slogger_t, devb_t) name types this file does not declare (the file must compile alone), so they are in the reviewed grants file below,
#   which --merge-policy appends after the learned system types. Connections between G17 types stay decided here (G17F: none is granted).
# - g17_test_t: the test drivers test_iru_proc / test_edge_proc (and timeout, and the programs they fork + exec: v2v-iru-cloud, v2v-edge,
#   v2v-vehicle-g17, g17-radio-sim, v2v-sentinel, v2v-iru-host) at uid 1200. Before G17d they ran as type "default": secpolgenerate does not
#   learn rules for "default", their non-root channel connects failed even in the develop boot ("timeout: xpipe: Operation not permitted",
#   rc=125 for both), and the secure boot would fail the same way. A test harness type is outside the isolation claims; it never connects to
#   a G17 type. Its learned rules are kept by --merge-policy (keep-learned) once a develop boot has run with it; the seed block below covers
#   what the 2026-11-14 develop boot showed (fork + exec, pipe(), files, /dev/urandom).
# - Abilities learned but NOT granted, by design: host_srv_t fork (the resource manager's own self-check forks after procmgr_ability deny +
#   lock and must FAIL; the permissive develop boot let it succeed, hence "sandbox was not applied; refusing to serve" there), edge_unit_t
#   spawn (learned from probe P5, the spawn the policy must refuse), supervisor_t setuid / setgid 1200 (learned because the develop boot has
#   no policy, so no default_spawn_type, and v2v-edge dropped to 1200 while still supervisor_t), any channel_connect to a G17 type
#   (host_srv_t -> edge_unit_t came from probe P2). Table and reasons: A_NOTES_G17.md, section G17d.
# merge-policy system-grants: g17_sysconn.txt
# merge-policy keep-learned: g17_test_t

type supervisor_t;
type edge_unit_t;
type edge_probe_t;
type host_srv_t;
type radio_feed_t;
type g17_test_t;

# ---- type change on spawn (G17c): v2v-supervisor starts v2v-edge with a plain posix_spawn (no type id), so without this rule the edge unit
# would inherit supervisor_t. default_spawn_type forces the child of a supervisor_t process into edge_unit_t.
default_spawn_type supervisor_t edge_unit_t;

# ---- path attach: who may register which path. G17F: the radio path belongs to the probe type (v2v-edge reads the radio from a FIFO and
# attaches nothing; on a target with a radio driver that driver would get its own attach rule).
allow_attach edge_probe_t /dev/v2v_radio;
allow_attach host_srv_t /dev/v2v_ttl;

# ---- channel connect: G17F: no G17 type may connect to another G17 type's channel (no rule here; by default a process connects only to
# channels of type "default"). Connections of G17 types to system services (pipe manager, slogger2, random ...) are the reviewed grants of
# g17_sysconn.txt; a learned connection to a G17 type is never kept by --merge-policy.

# ---- abilities (each type gets only what its start-up needs; everything else stays denied in secure mode)
# prot_exec on every type: all G17 programs except the static probes are dynamically linked (libc, libcrypto; v2v-supervisor also dlopen()s
# libslog2), and the runtime linker maps those libraries executable.
# supervisor_t: spawn (posix_spawn of the edge unit); waitpid and SIGTERM to a child that has dropped to another uid (wait, signal 15); prot_exec
# (dynamically linked, dlopen of libslog2). G17F: root
# only (no "nonroot"): v2v-supervisor runs as root and never drops, so a non-root supervisor_t process gets none of these.
allow supervisor_t self:ability {
    spawn
    prot_exec
    wait
    signal:15
};
# edge_unit_t, nonroot: prot_exec (dynamically linked; libraries may be mapped after the drop). G17F: no pathspace / public_channel /
# priority - v2v-edge attaches no path (it reads the radio FIFO); those were used only by probes P0 / P3, which now run as edge_probe_t.
allow edge_unit_t self:ability {
    nonroot
    prot_exec
};
# edge_unit_t, root only: setuid / setgid 1200 - v2v-edge starts as root (child of the root supervisor) and drops itself with setgroups +
# setgid + setuid while still root (G17F: moved out of the nonroot block; the develop boot learned the drop in a root block, then under
# supervisor_t); map_fixed below.
allow edge_unit_t self:ability {
    setuid:1200
    setgid:1200
};
# edge_probe_t (G17F, probes only): g17-probe P0 attaches /dev/v2v_radio and serves it (the positive control), P3 tries to attach a host-like
# path (allow_attach refuses it). The probe runs as root: pathspace + public_channel to attach and create its channel, priority, map_fixed
# and prot_exec as the develop boot learned for the probes (then recorded in edge_unit_t's root block; P0 passed the secure round with
# prot_exec granted). Root only.
allow edge_probe_t self:ability {
    pathspace
    public_channel
    priority:0-253
    map_fixed
    prot_exec
};
# host_srv_t, nonroot: prot_exec (dynamically linked: v2v-vehicle-g17 runs at uid 1000 from its start, the resource manager after its drop).
allow host_srv_t self:ability {
    nonroot
    prot_exec
};
# host_srv_t, root only (G17F: pathspace and public_channel were in the nonroot block): the resource manager attaches /dev/v2v_ttl and
# creates its channel BEFORE it drops (pathspace, public_channel; priority below), then --drop-uid 1000 = setgroups + setgid + setuid while
# still root (setuid / setgid 1000, G17c: the same start with and without a policy); "on -T host_srv_t -u 1000:1000" sets the uid of
# v2v-vehicle-g17 while root. The develop boot learned all of them in host_srv_t's root block. After the drop, and in v2v-vehicle-g17,
# host_srv_t can attach nothing and change no uid.
allow host_srv_t self:ability {
    pathspace
    public_channel
    setuid:1000
    setgid:1000
};
# radio_feed_t, nonroot: prot_exec - g17-radio-sim runs at uid 1300 from its start and is dynamically linked (libcrypto); map_fixed below.
allow radio_feed_t self:ability {
    nonroot
    prot_exec
};

# ---- G17d: abilities the develop boot showed are needed for the programs to start (root-only blocks carry no "nonroot": they are not
# available after a process drops its uid)
# map_fixed: the runtime linker / libc map segments at fixed addresses; learned for every type that ran (and for every system service).
# supervisor_t, edge_unit_t: root only (v2v-supervisor stays root; v2v-edge loads before it drops to 1200 - learned in supervisor_t's root
# block, the develop boot ran v2v-edge as supervisor_t). host_srv_t, radio_feed_t: nonroot (v2v-vehicle-g17 and g17-probe P2 start at uid
# 1000, g17-radio-sim at 1300 - learned in the nonroot blocks).
allow supervisor_t self:ability {
    map_fixed
};
# ---- G17e (2026-11-14, after the secure boot evidence/g17/qnx_secpol.serial.clean.log lines 43 / 61: "[supervisor] ERROR: posix_spawn
# /system/bin/v2v-edge: Operation not permitted"): settypeid:edge_unit_t, root only, for supervisor_t.
# - The change of type that default_spawn_type forces is a spawn with a type id. abilities.html: settypeid (PROCMGR_AID_SETTYPEID) is needed
#   to "specify a type identifier in a call to posix_spawn()", with a subrange of the type ids allowed; using_security_policies.html: "the
#   ability to change ... [the type] of their children is controlled by an ability". supervisor_t had spawn but lacked settypeid, so the forced
#   switch to edge_unit_t was refused with EPERM. Same secure boot, same nonroot "spawn" grant: g17_test_t (no default_spawn_type) spawned
#   v2v-edge and v2v-iru-cloud without error (test_edge_proc 16 PASS, test_iru_proc 6 PASS); only the spawn with the forced type failed.
# - The develop boot could not learn it: it has no G17 policy, so no default_spawn_type, and v2v-edge stayed supervisor_t (no type change).
# - Subrange edge_unit_t only: the supervisor can give its children no other type (never host_srv_t). Root only (no "nonroot"): v2v-supervisor
#   runs as root and never drops; a non-root supervisor_t process cannot switch, so secpolcompile has no non-root privilege gain to require
#   gain_priv for (secpol_language.html: gain_priv is required when a NON-root process can gain privileges by switching type).
# - Not granted: setuid / setgid 1200 for supervisor_t (v2v-edge drops itself under edge_unit_t, as before), spawn for edge_unit_t.
allow supervisor_t self:ability {
    settypeid:edge_unit_t
};
# priority: learned in the root block of host_srv_t (the resource manager attaching /dev/v2v_ttl before --drop-uid; QNX confirms "resmgr_attach
# OK" in the secure round); root only, so no host_srv_t process can raise a priority after it dropped its uid. G17F: edge_unit_t keeps only
# map_fixed (root: v2v-edge loads before it drops); its priority came from probes P0 / P3 and moved to edge_probe_t.
allow edge_unit_t self:ability {
    map_fixed
};
allow host_srv_t self:ability {
    nonroot
    map_fixed
};
allow host_srv_t self:ability {
    priority:0-253
};
allow radio_feed_t self:ability {
    nonroot
    map_fixed
};
# g17_test_t (test harness only, outside the isolation claims). G17F: this block is the WHOLE reviewed grant; --merge-policy keeps a learned
# g17_test_t ability only if it is granted here or in g17_sysconn.txt (anything else is dropped and listed as WARN). Each item and why:
#   fork, spawn        tests/test_iru_proc.c and tests/test_edge_proc.c fork + exec the programs under test; timeout spawns the driver
#   prot_exec, map_fixed  dynamically linked programs (runtime linker)
#   setuid:1200, setgid:1200  the drivers start at uid 1200 and fork + exec v2v-edge / v2v-sentinel, which call their own drop
#                      (setgroups + setgid + setuid 1200) as uid 1200; "on -T g17_test_t -u 1200:1200" sets the uid after the type.
#                      Learned in the nonroot block of the develop boot (evidence/g17/qnx_learn.serial.clean.log, rules for g17_test_t)
#   pgrp               timeout puts the driver in its own process group (setpgid); learned in the same block
# No pathspace, no attach, no settypeid, no channel to a G17 type (preflight and merge refuse them).
allow g17_test_t self:ability {
    nonroot
    fork
    spawn
    prot_exec
    map_fixed
    setuid:1200
    setgid:1200
    pgrp
};
