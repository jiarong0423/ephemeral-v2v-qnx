# How "594,000" and "1,782,000" simulated runs follow from the ablation CSV

Written 2026-11-26 09:04 (date). Note, checked only against the files listed below.

## Inputs (staged paths, relative to this folder)

- `qnx_reg_20261118/abl_full/spec2_b4m4abl.csv` - per-setting table, one row per setting (sha256 1a4eee1885479d50dff178e16678f58e204086bf6023bd361c5d5a84177ea657).
- `qnx_reg_20261118/run_abl_full.sh` - the runner that produced it.
- `qnx_reg_20261118/abl_full/run.log` - the runner's merge log.
- `qnx_reg_20261118/effects_by_clr.py` / `effects_by_clr.txt` - the effect table quoted in README.
- Not staged: `abl_full/spec2_b4m4abl_runs.csv` (one row per run, 201,124,095 bytes, over the 100 MB GitHub file limit). Row counts below for it were read from the local original.

## Derivation

1. Design: `run_abl_full.sh:2` says "8910 settings x 200 trials, 40 shards"; `run_abl_full.sh:8` sets `SH=40; TR=200`.
2. Per-setting CSV: 8,911 lines = header + 8,910 setting rows. Column 3 = `arm`, 11 = `clr_cm`, 22 = `trials`, 23 = `takeovers`.
   Every one of the 8,910 rows has `trials=200`.
3. All clearances: 8,910 rows x 200 trials = **1,782,000** runs.
   Same number: `run.log:44` "merged spec2_b4m4abl_runs.csv rows 1782000", `run.log:43` "merged spec2_b4m4abl.csv rows 8910",
   and `effects_by_clr.py:6` `assert len(d)==1782000`.
4. Per clearance: rows with `clr_cm` = 50, 70, 100 are 2,970 each. 2,970 x 200 = **594,000** runs at `50 cm`
   (also 594,000 at 70 and at 100; the runs CSV has 594,000 rows for each clearance).
5. The 2,970 rows at `50 cm` are 990 per arm (A00 = waiting baseline, A01 = give-way rule, A11 = rule + map).
   990 is the `pairs=  990` of `effects_by_clr.txt:19`. 990 x 200 = 198,000 runs per arm.
6. Take-over rates at `50 cm` from the per-setting CSV (sum of `takeovers` / sum of `trials`):
   - A00: 63,453 / 198,000 = 32.047 % (`effects_by_clr.txt:4`, first column)
   - A01: 120 / 198,000 = 0.061 % (`effects_by_clr.txt:4`, second column)
   - A11: 152 / 198,000 = 0.077 % (`effects_by_clr.txt:4`, third column)

## Wording point for the owner

"32.05% -> 0.061% across 594,000 simulated runs" counts all three arms at `50 cm`.
The two numbers compared (A00 vs A01) come from 198,000 + 198,000 = 396,000 of those runs (990 paired settings x 200 trials);
the remaining 198,000 are arm A11. The 95% CI `29.55-34.40` (`effects_by_clr.txt:19`) is a seed-cluster bootstrap over the
per-trial runs CSV, which is not staged, so the CI cannot be recomputed from the repo; the three rates in step 6 can.
